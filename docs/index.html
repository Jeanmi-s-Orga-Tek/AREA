AREA

Plateforme d'automatisation académique inspirée d'IFTTT/Zapier. FastAPI orchestre les actions/réactions, les clients web et mobile permettent de créer et suivre vos AREAs, et les connecteurs OAuth relient vos comptes.

7 services 17 actions 17 REActions Web + Mobile
Voir la documentation API Démarrer en local Explorer les connecteurs

Ce que contient la stack

  • Backend FastAPI (JWT + OAuth, YAML actions/réactions, handlers webhook/polling, interpolation de payload)
  • Moteur AREA qui relie actions → REActions via area_engine et exécuteurs dédiés
  • Front React/Vite + mobile React Native pour connecter des services et créer des AREAs
  • Docker Compose : API 8080 · Web 8081 · Adminer 8123 · PostgreSQL

Mises à jour 2025

Ce qui est nouveau

Connecteurs OAuth

Google, Microsoft, GitHub, Spotify, Trello, Discord et Timer sont préconfigurés avec scopes, icons et couleurs (Backend/config/providers.yaml).

  • Connexion/déconnexion de comptes via /services/{service}/connect
  • Renouvellement de tokens (/services/.../refresh)
  • Plusieurs flows : web et mobile

Handlers webhook & polling

Nouvelle architecture d'actions gérée par app/handlers : mapping des events, validation de signature, et polling périodique.

  • GitHub/Trello via webhooks (/webhooks/github, /webhooks/trello)
  • Polling worker (python -m app.polling_worker) pour Gmail, Drive, Outlook, Spotify, Timer…
  • Payloads aplatis prêts pour l'interpolation des REActions

UI web & mobile complètes

Le client React/Vite (Nginx) et l'app React Native couvrent authentification, connexion de services et création d'AREAs.

  • Routes protégées par JWT, callback OAuth, gestion de profil
  • Builder AREA (choix action/réaction + paramètres dynamiques)
  • APK générée dans mobile/apk (exposée par l'image web)

Provisionning automatique

Les YAML de Backend/services, actions et reactions sont injectés en base au démarrage via db.create_db_tables().

  • Synchronisation des champs (description, icône, scopes, paramètres)
  • Actions/REActions ordonnées par service
  • Prêt pour ajouter de nouveaux connecteurs en éditant un seul fichier

Pipeline

Architecture d'exécution

API & Auth

FastAPI sert /user, /services, /areas, /oauth et /about.json.

JWT (password) + OAuth 2.0 (code flow) pour les providers listés.

Moteur AREA

area_engine transforme une Action en REAction : vérification des conditions, interpolation des variables et exécution via les exécuteurs de app/executors.

Handlers

app/handlers mappe chaque évènement (push, new_card…) aux AREAs concernées. Webhook Manager gère la création/cleanup des webhooks côté services.

Persistance & outils

PostgreSQL stocke utilisateurs, services connectés, AREAs. Adminer accessible en 8123 pour inspecter la base.

1 Connectez un service via OAuth (web ou mobile).
2 Créez une AREA (Action + REAction + paramètres).
3 Un handler reçoit l'évènement (webhook ou polling).
4 Le moteur exécute la REAction en interpolant le payload.
5 Suivez l'exécution dans les clients ou via les logs.

Usage

Déclencheur temporel pour toute REAction d'un autre service.

Les actions/REActions sont décrites en YAML puis importées automatiquement en base au démarrage du backend.

Déploiement

Démarrer la stack

Docker Compose (full stack)

  1. Créer un .env avec POSTGRESQL_URI, SMTP_*, API_BASE_URL et les clés OAuth.
  2. Depuis la racine : docker compose up --build
  3. Accès : API http://localhost:8080 · Web http://localhost:8081 · Adminer http://localhost:8123

Les APK mobiles générées sont servies via le conteneur web (/client.apk).

Backend seul

  1. Python 3.9 · cd Backend && python -m venv .venv && source .venv/bin/activate
  2. pip install -r requirements.txt
  3. Exposer les variables : POSTGRESQL_URI, SMTP_SERVER, SMTP_PORT, EMAIL_USERNAME, EMAIL_PASSWORD, API_BASE_URL, secrets OAuth (voir config/providers.yaml).
  4. uvicorn app.main:app --reload --port 8080
  5. Optionnel : lancer le worker polling python -m app.polling_worker

Configurations clés

  • PROVIDERS_CONFIG pointe par défaut sur Backend/config/providers.yaml.
  • Secrets webhook : GITHUB_WEBHOOK_SECRET, TRELLO_WEBHOOK_SECRET.
  • OAuth web callbacks : http://localhost:8081/auth/callback/<provider> (web) ou ${API_BASE_URL}/auth/callback/<provider> (mobile).
  • Base de données : Postgres (pool configuré dans app/db.py).

API

Points d'entrée utiles

Découverte

GET /about.json retourne l'heure serveur, l'IP appelante et la liste des services/actions.

Utile pour les clients web/mobile pour construire l'UI dynamiquement.

OAuth & services

GET /oauth/providers, /oauth/authorize/{provider}/{flow}, /oauth/callback/{provider}
GET /services (catalogue), /services/my (comptes connectés)

AREAs

POST /areas (création), GET /areas (liste), PATCH /areas/{id}/toggle, DELETE /areas/{id}.

Les paramètres Action/REAction sont validés selon les YAML chargés.

Webhooks

POST /webhooks/github et /webhooks/trello traitent les évènements entrants et déclenchent les AREAs correspondantes.

Les signatures peuvent être vérifiées via les secrets d'env.

curl -X GET http://localhost:8080/about.json | jq
curl -X POST http://localhost:8080/areas \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "GitHub PR → Trello carte",
    "action_service_id": 2,
    "action_id": <id_action_pr>,
    "reaction_service_id": 6,
    "reaction_id": <id_reaction_create_card>,
    "action_parameters": {"repository.full_name": "owner/repo"},
    "reaction_parameters": {"name": "PR {{pull_request.title}}", "desc": "{{pull_request.body}}"},
    "is_active": true
  }'

Interfaces

Clients web & mobile

Web (Front/AREAA)

React 18 + Vite + TypeScript, servi par Nginx dans Docker.

  • Pages : login/register, services connectés, profil, liste et création d'AREAs
  • Scripts : npm run dev, npm run build, npm run test

Navigation native, context API, écrans login/services/AREAs/settings.

  • Scripts : npm run android, npm run ios, npm test
  • APK générée dans mobile/apk (montée dans l'image web)
  • PKCE supporté via le flow mobile des providers
